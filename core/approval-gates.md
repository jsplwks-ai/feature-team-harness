# 使用者確認關卡

## 關卡與執行模式

部分關卡依 Claude Code 當下執行模式決定是否放行。Coordinator 依系統提示判斷目前是否為 auto mode；無法判斷時視為一般模式。

| 關卡 | 一般模式 | auto mode |
|---|---|---|
| 需求內容及範圍（Step 2.5） | 須確認 | 可直接放行 |
| 採用輕量模式（`review-modes.md`） | 須確認 | 可直接放行 |
| 最終實作計畫（Step 4.5） | 須確認 | 可直接放行 |
| 需求或架構的重大變更 | 須確認 | 可直接放行 |
| 無法排除的重大風險及其接受決策 | 須確認 | 須確認 |
| Harness 核心流程或角色權限變更 | 須確認 | 須確認 |
| 平票或無法解決的評審分歧 | 須確認 | 須確認 |
| 刪除檔案（含 Phase 7 清理） | 須確認 | 須確認 |

## 補充規則

- auto mode 放行只免除關卡等待，不免除 Step 2.3 的逐項釐清；需求不清楚時仍須詢問。
- 放行的關卡仍須寫入工作紀錄「關卡紀錄」，註明「auto mode 放行」。
- 測試執行與 Git 寫入另依 `testing-and-git.md` 確認，不受本表 auto mode 欄影響。

## 詢問方式

- 有明確選項時使用 `AskUserQuestion`，一次最多 4 題，每題須能獨立閱讀（使用者可能看不到先前輸出）。
- 需求全文、計畫全文等長內容，先寫入 `SESSION_DIR` 檔案，於問題中附檔案路徑與重點摘要。
- 使用者提出修改時，回到對應步驟，修改後重新確認。

## 紀錄格式

工作紀錄「關卡紀錄」每筆包含：時間、關卡、模式（一般／auto）、結果（確認／修改／放行／拒絕）、使用者意見摘要。
