# Agent 獨立性與派遣規範

## 獨立性

- 架構評審者 A／B／C、Reviewer A／B／C 每位都是新派遣的 Subagent，擁有獨立 Context。
- 第一輪獨立分析必須在讀取其他 Agent 結論之前完成。
- Agent 可共享相同的需求、規格、程式碼及審查材料，但不得共享尚未完成的個別判斷。
- 第一輪派遣訊息不得包含其他 Agent 的結論，也不得提示其他 Agent 的傾向。

## 轉達

- Subagent 之間無法直接溝通，交換意見、交叉審核及投票皆由 Coordinator 轉達。
- 第二輪起，Coordinator 以 `SendMessage` 對同一個 Agent 繼續對話（保留其第一輪 Context），提供其他 Agent 第一輪結果的檔案路徑。
- 轉達時不得刪減、改寫或摘要他方結論；直接提供原始檔案。
- `SendMessage` 無法延續時（例如接續舊流程、Agent 已不存在），新派遣同角色同身分的 Agent，提供該 Agent 先前產出的檔案及原輸入材料，並於工作紀錄註明。

## 派遣訊息必備內容

1. `HARNESS_ROOT`、`PROJECT_ROOT`、`SESSION_DIR` 絕對路徑。
2. 角色身分（例如「評審者 B」「Task T-03 的 Developer」）。
3. 任務目標與完成判斷標準。
4. 輸入材料的檔案路徑（傳路徑，不貼全文）。
5. 輸出位置（檔案路徑）或回傳格式。
6. 本次特有的限制（例如已確認的測試範圍、不得修改的檔案）。

## 平行與等待

- 同一輪的 A／B／C 於同一則訊息中平行派遣。
- Subagent 完成時會通知 Coordinator；等待期間不得輪詢、不得預測或捏造結果。
- 一輪中所有 Agent 皆完成後，才進入下一輪。

## 失敗與重試

| 情況 | 處理 |
|---|---|
| Agent 執行失敗、逾時或輸出不完整 | 以相同輸入重新派遣 1 次 |
| 重試後仍失敗 | 該項標記 `BLOCKED`，寫入工作紀錄，向使用者回報並詢問處理方式 |
| 輸出格式不符但內容可用 | 以 `SendMessage` 要求該 Agent 補正，不算重試 |

不得以 Coordinator 自行產出的內容代替失敗 Agent 的結論。
