# 程式碼審查標準

## 審查基準

Reviewer 唯讀檢查：

- 本次 Diff（範圍見 `testing-and-git.md` 的「審查範圍」）。
- 新增及修改的程式碼與其相關程式。
- 相關 System Specification 及本次規格草稿。
- 實作計畫及任務驗收條件。
- 測試內容及執行結果（以 Developer 回報與 Coordinator 紀錄為準）。

## 審查項目

| 項目 | 檢查內容 |
|---|---|
| Requirement | 是否符合已確認需求 |
| Correctness | 邏輯及業務規則是否正確 |
| Architecture | 是否符合既有架構與核准設計 |
| Code Quality | 命名、可讀性、可維護性 |
| Performance | 是否存在效能問題 |
| Security | 是否存在安全性漏洞 |
| Compatibility | 是否影響既有功能及相容性 |
| Testing | 測試是否完整且有效 |
| Specification | 規格草稿與程式碼是否一致 |

## 嚴重程度

| 等級 | 定義 | 處理原則 |
|---|---|---|
| Critical | 重大錯誤、安全漏洞或可能造成嚴重資料損失 | 必須修正，不得直接通過 |
| Major | 重要功能錯誤、業務邏輯錯誤或重大架構問題 | 必須修正或取得明確風險決策 |
| Minor | 一般品質、維護性或非關鍵問題 | 記錄並決定修正或接受 |
| Suggestion | 非必要改善建議 | 可列為後續改善事項 |

## 問題必填欄位

問題 ID（`{Reviewer}-{序號}`，例如 `RA-01`）、嚴重程度、審查項目、檔案及行號、具體證據、問題原因及影響、建議修正方式。

## 修正後重新審查

| 修正內容 | 重新審查者 |
|---|---|
| 含 Critical 或 Major | 三個 Reviewer 重新審查受影響 Diff（輕量模式為 Reviewer A） |
| 僅 Minor | 提出該問題的 Reviewer 單獨複查 |

每次修正後都必須重新審查受影響的異動，不得沿用舊審查結果。

## 最終通過條件

- 無未解決的 Critical 問題。
- 無未解決的 Major 問題；如需接受風險，必須有明確依據及使用者確認。
- Minor 問題已有處理決策。
- Suggestion 已記錄。
- 必要測試全部通過（有執行證據）。
- 規格草稿與實際程式碼一致。
- 三個 Reviewer 已完成獨立審查及交叉確認（輕量模式為 1 個 Reviewer 完成審查）。
- 重大爭議均已解決或經使用者決策。
